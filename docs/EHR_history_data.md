根据EHDS法规的规定，所有EHR系统（电子健康记录系统）中的历史数据，只要属于优先类别的个人电子健康数据，都有被转换为符合EHDS互操作性标准的潜在需求，而不仅仅是医疗器械产生的数据。这一需求的核心驱动力，来源于法规对数据持有者（health data holder） 的义务规定，而非仅针对设备制造商。
具体分析如下：
1. 核心义务主体：数据持有者（Health Data Holder）
EHDS法规要求数据持有者（包括医院、诊所、实验室、药房、公共卫生机构等）在特定时间点后，必须能够响应数据请求，提供符合规范的电子健康数据。这意味着，即使数据是多年前在旧EHR系统中记录的，只要它属于优先类别，且数据持有者收到了合法的数据请求（如出于二次使用目的的数据许可），就必须以符合EHDS标准的格式提供这些数据。
2. 与医疗器械数据的区别
虽然医疗器械数据也是EHR系统数据的一部分，但转换需求的覆盖范围更广：
数据来源转换需求驱动力最终责任方医疗器械产生的数据（如CT、MRI、血糖仪数据）法规要求设备制造商确保其产品能够输出互操作的数据；数据持有者需要整合并提供这些数据。医疗器械制造商（确保输出可互操作格式）+ 数据持有者（确保数据被正确存储和提供）EHR系统内的所有其他数据（如电子处方、患者摘要、化验报告、出院小结、手术记录、护理记录、免疫接种记录等）法规要求数据持有者确保其持有的整个EHR系统（无论是哪种型号）中的数据，在需要时能够被提取并以标准格式提供。数据持有者（医院、诊所等）—— 他们需要检查自己的EHR系统是否具备这种能力，如果旧系统不具备，则需要通过系统升级、接口改造或数据迁移来实现。
结论：医疗器械历史数据的转换需求是EHR系统历史数据转换需求的一个子集。所有在EHR系统中存储的、属于优先类别的历史数据，都面临转换需求。
3. 转换需求的触发时间节点
这种“转换需求”并非立即对所有历史数据生效。法规通过分阶段实施，给出了一个过渡期：

2027年3月26日：法规全面适用，数据持有者需要开始履行新义务，但数据格式转换有更长的过渡期。
2029年3月26日：所有EHR系统（包括旧系统） 中处理最优先的5类数据（患者摘要、电子处方、电子配药、化验结果、出院小结）的历史数据，必须能够以符合EHDS的格式被访问和传输。
2031年3月26日：剩余优先类别数据（医学影像及其报告、医疗检测结果等）的转换截止日期。

4. 转换的形式：并非全部“重新输入”
这种转换不意味着将所有历史数据重新手动输入一个新系统。EHDS法规要求的是数据的可访问性和可互操作性，通常通过以下方式实现：

数据映射与标准化：将旧EHR系统中的数据字段映射到新的标准格式（如HL7 FHIR或OMOP CDM）。
系统接口升级：更新EHR系统的软件，使其能够输出标准格式的数据（例如，添加一个API接口）。
数据提取与迁移：将历史数据从旧系统批量导出，转换为标准格式后存储在新的、符合规范的数据仓库中。

5. 唯一的豁免情况：模拟/纸质数据
法规明确豁免了对从未数字化的历史数据进行转换的要求。根据D5.1 Guideline on data description（第5.1节）：法规不强制要求将原有纸质的或模拟形态的健康数据数字化。但是，如果这些数据以前已经被录入到某个EHR系统中了（即已经是电子数据），那么它就在转换的范围内。

FHIR的角色：

“HL7 FHIR... 是广泛用于临床诊疗环境、EHR系统和健康信息交换系统的标准，用于定义和交换健康数据”（D5.1 Guideline on data description）。

法规和指南提到了多种可能的标准，包括：

OMOP CDM：用于分析研究（参考资料中明确了其角色）
CDISC：用于临床试验数据
其他国际化标准（如SNOMED CT、LOINC等编码系统）

2. 转换需求的具体规则
根据EHDS法规，历史数据的转换要求可以总结如下：
数据类别要求是否必须用FHIR优先类别数据（患者摘要、电子处方、化验结果、出院报告等） 到2029/2031年，必须能够以欧洲电子健康记录交换格式（European electronic health record exchange format）输出是，法规明确规定优先数据类别的交换格式基于FHIR标准（参见《EHDS法规》第14条及相关实施法案）其他EHR数据（如手术记录、护理记录等）取决于未来扩展的规范，目前尚无强制转换要求不一定用于研究的数据（二次使用）取决于数据访问机构（HDAB）的要求，可能要求转换为OMOP CDM等其他模型不一定，取决于具体数据请求
关键点：法规要求的是“能够提供互操作格式的数据”，而非必须将所有历史数据永久转换为FHIR存储在本地。许多实现方式是按需转换——在收到数据请求时才将历史数据从原格式映射并转换为目标格式。
3. 转换的实操方式：并非全量重写历史数据
根据参考资料（D6.1 Guideline on health data holders），数据转换可以通过以下方式实现，而非全部“重新输入”：

数据映射：建立旧系统字段到FHIR资源的映射关系，实现按需转换
接口升级：为旧EHR系统添加FHIR API接口，使其能够实时输出FHIR格式数据
批处理导出：将历史数据批量导出，转换为FHIR格式后存储在新系统中
